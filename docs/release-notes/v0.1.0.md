# XGrid 0.1.0

First packaged release. XGrid is a desktop Xbox emulator: an Avalonia shell
around a maintained build of [xemu](https://xemu.app) 0.8.139, whose source
lives in this repository under `xemu/`. The shell and the emulator run in one
process.

## Downloads

| Package | Runtime |
|---|---|
| `XGrid-cli-win-x64.zip` / `XGrid-frontend-win-x64.zip` | Windows 10/11, x64 |
| `XGrid-cli-linux-x64.tar.gz` / `XGrid-frontend-linux-x64.tar.gz` | glibc Linux, x64 |
| `XGrid-cli-osx-x64.tar.gz` / `XGrid-frontend-osx-x64.tar.gz` | macOS 11+, Intel |
| `XGrid-cli-osx-arm64.tar.gz` / `XGrid-frontend-osx-arm64.tar.gz` | macOS 11+, Apple Silicon |

Every archive is self-contained: no .NET runtime has to be installed. The same
folder carries `COPYING`, `LICENSE`, `THIRD_PARTY_NOTICES.md`, `README.md`, this
file as `RELEASE-NOTES.md`, and a `VERSION` file. `SHA256SUMS-<rid>.txt`,
`SHA256SUMS.txt` and `package-manifest.json` are published beside the archives.

**The Windows frontend archive also carries the emulator**, under `core/xemu/`:
the standalone `xemu.exe`, the in-process `xgrid_core.dll` and the runtime DLLs
they import. That is the emulation core, built from the `xemu/` tree in this
repository. The Linux and macOS frontend archives contain the shell only; the
core is currently a Windows build.

## Quick start

XGrid ships no firmware, no EEPROM and no game data; supply your own legally
obtained files (a BIOS image, an MCPX ROM, an EEPROM dump and an HDD image or a
disc image).

1. Start `XGrid.Frontend.Avalonia`.
2. In **Settings**, set the BIOS, MCPX ROM, EEPROM and storage paths, and add
   your game folders to **Library**.
3. Pick a title in **Library**, or press **Power on** for the dashboard.

`F8` saves a screenshot of the current frame to the `screenshots` folder beside
`settings.json`, `F11` toggles full screen and `F5` powers the console on or
off. Settings -> System -> **Core hosting** chooses
between the in-process core (default) and a separate core process.

The `XGrid.Cli` archive is the managed reference emulator used to validate the
core: the four accurate 1B goldens and the kernel test suite run against it.
`XGrid.Cli boot --help` lists its options.

## Highlights

- **One application.** The shell loads the core library, presents its frames and
  feeds it the pad; there is no second window to manage. The separate-process
  host stays available as a fallback.
- **The real boot chain.** Retail MCPX ROM through the 2BL and the kernel into
  the dashboard XBE: SMC, PCI, IDE (HDD and ATAPI DVD, plain ISO, compressed CHD
  and ZArchive), USB/OHCI with the Xbox hub and XID pad, SMBus/EEPROM, RTC,
  PIT/PIC, AC'97 and the APU with its DSP microcode, and the NV2A.
- **NV2A with an OpenGL renderer**, the QEMU TCG i386 CPU core and netplay, all
  from the maintained xemu tree.
- **Usability**: keyboard and XInput pads, per-title settings, persistent EEPROM,
  save/load states, library scan, filters and scaling, and a themeable desktop UI.

## Known limitations

- **The core is a Windows build.** Linux and macOS frontends run the shell
  without the bundled core; point them at a core built from `xemu/` with
  `scripts/build-native-xemu.ps1` (or set `XGRID_XEMU_CORE`).
- **Real-game compatibility is early.** The compatibility matrix
  (`docs/compatibility.md`) tracks homebrew samples and a few real titles; treat
  those rows as the supported surface, not "any Xbox disc".
- **No OS installer.** The archives are portable and write only to the per-user
  data directory.
- **Unsigned binaries.** macOS quarantines a downloaded archive until
  `xattr -dr com.apple.quarantine <folder>` is run, and Windows SmartScreen shows
  its uninformed warning. Neither package is code-signed or notarized.

## Validation

Cut from a tree whose gates pass locally (CI is disabled on this repository):

- `dotnet build XGrid.sln -c Release` with warnings as errors; full test suite
  green; `dotnet format --verify-no-changes` clean.
- Emulator gates at 1B steps: triangle `gl+replace` `4F1FCBC0`/`7DAB63EB`,
  menu `gl+replace` `B06BA6E5`/`F5D61C94`, accurate goldens `A1740DE0` /
  `7A860ED7` (triangle) and `4EF1FBF6` / `B6116DAE` (menu) with
  `BackendUnsupported=0`.
- Kernel test suite smoke: 7/7 rows, suite log byte-identical at
  792,800,535 steps.
- In-process core through the real shell: no child process, the emulation CPU is
  spent in the shell, and the separate-process host still spawns `xemu`.
- Packages: `scripts/package-verify.ps1` reports `PACKAGE PASS` for all four
  RIDs (license set, archive contents, bundled core, SHA-256, manifest, CLI
  version).
